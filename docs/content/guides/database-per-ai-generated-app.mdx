### What we'll build

- A generated app whose Actors store its data in SQLite, with tables the app defines in its own code.
- Migrations that run inside the Actor when it starts, so a new release can change the schema.
- A deploy step that ships only code, with no database to create, connect, or pay for per app.
- A way for your platform to read an app's data through the same Actor actions.

### Similar tools

This is the same job as Supabase for AI builders, Neon for AI agents with claimable Postgres, Turso with a database per app, or Convex for AI app builders. On Rivet the database is part of each app's Actors, so it exists as soon as the app gets its first request and needs no connection string.
