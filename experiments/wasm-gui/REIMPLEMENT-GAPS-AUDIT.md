# REIMPLEMENT-ON-CLEAN-MAIN — Completeness-Audit Addendum

**Verdict:** The plan's *runtime-code* manifest (K1–K15, DIAGNOSTICS, DROP, CARRY-AS-DESIGN, SIGN-OFFS) is substantially complete and accurate — roughly **85% complete**. What it systematically under-captures is the **non-runtime layer** that the runtime depends on to actually render: the host-driver VM-config + I/O contract, the toolchain/link constraints for threaded GTK guests, the fixture-staging set that stands in for missing fork, the FFI ABI detail, and several **governance corrections** where the plan still presents retracted "floors" and optional timer-fallbacks as settled. Net: **9 high-severity gaps, 3 high-severity corrections, ~17 medium, ~10 low/info, 1 discarded false gap.** The main plan needs edits — the floor/wakeup corrections and the host-config DoD are load-bearing.

After de-dup across the 8 slices, the single most important miss is the **host-driver runtime contract** (CPU-time opt-out + fuel + memory raises on the right code paths, plus the out-of-band framebuffer scrape and XTEST-over-host-socket input path): without it the desktop goes black at 30–70s with no diagnostic, and a remote-client AgentOs port cannot get frames or input at all.

## 1. HIGH-SEVERITY GAPS

### H1 — Threaded-guest build/link recipe: errno-TLS, `__wasi_init_tp`, direct-link, EAI_* shim
**What:** Threaded C++/GtkBuilder guests won't *link* unless `host_socket.o`/`host_pipe_dup.o` (wasi-libc sockets/pipe-dup patches) **and expat** are built with `-matomics -mbulk-memory` so their `errno` refs are TLS — one non-TLS-errno object forces `errno` into non-TLS `.bss` and every TLS-errno object (gtksourceview's `gtkbuilder.c.o` via mousepad) fails `R_WASM_MEMORY_ADDR_TLS_SLEB against non-TLS symbol errno`. Separately `__wasi_init_tp` only resolves if the **final link is a DIRECT (non-libtool) clang link** — libtool nests archives and never archive-pulls libc.a's `__init_tls.o` → undefined-import LinkError at instantiate. Also add `EAI_SOCKTYPE/EAI_SERVICE/EAI_OVERFLOW` to compat `netdb.h`.
**Evidence:** M8-STATUS-LOG.md:138–146; XUBUNTU-SPEC.md XU6 lines 680–682; PERF-OPTIMIZATION.md:1142–1148 (the `__wasi_init_tp` is load-bearing TLS init, *not* a no-op).
**Verdict:** KEEP. **Fold into:** NEW item **K16 (threaded-app build recipe)**, sibling to K12/K14. This is a *different TLS symbol class* than the EH `__wasm_lpad_context` fix the plan already names, and gates every threaded C++ and every GtkBuilder app.

### H2 — F1b cold-boot-windowed event-driven request-ingest (LANDED, default-ON)
**What:** A committed default-ON CORE win: replace the 250µs timer-polled sync-RPC *ingest* with an event-driven `select!`/`Notify` branch that dispatches inbound RPCs the instant they land, **windowed to cold boot** so it does not regress steady-state ir. Moved first-paint ~4.3s→~2.5s with no ir cost.
**Evidence:** PERF-OPTIMIZATION.md:392, :560–572.
**Verdict:** KEEP. **Fold into:** NEW item under the K1/K4 dispatch family. Distinct from K4 (drain passes) and from the "250µs pump = do not tune" steady-state floor. Omitting it regresses fp by ~1.8s; the cold-boot windowing is what prevents the ir regression (cf. F1-eager-warm null at :533).

### H3 — Host VM-config constraints: CPU-time opt-out + fuel + memory + separate xserver env
**What:** Long-lived GUI guests need three host-set raises or the desktop hard-collapses: (1) `AGENT_OS_V8_CPU_TIME_LIMIT_MS=0` per-process — default 30 000ms *true-CPU-time* watchdog kills the long-lived X server (~70s wall) → full-black; **the X server launches via a separate empty-env path (`s.execute("xserver",…)`, host main.rs:854/1634) so it needs its OWN execute_env.** (2) `maxWasmFuel=3600000` — default ~30s *wall-clock* fuel budget kills the X server ~30s in ("fuel budget exhausted"). These are **two independent timers**. (3) `maxWasmMemoryBytes=536870912` (512 MiB, 4× the ~128 MiB Workers default) or GTK/Xfce guests OOM. K10 fb-delta mitigates the futex storm but removes neither cap.
**Evidence:** host/src/main.rs:40, :765/:995/:1176/:1269/:2173/:2221; SPEC.md M6.4:361–372, M8.6 "FIX #1":754–765; crates/execution/src/javascript.rs:2083; crates/execution/src/wasm.rs:64.
**Verdict:** KEEP (usage/governance constraint — both channels exist on main). **Fold into:** NEW item **K17 (host VM-config DoD)**. K2 lists `maxThreads` but neither limit channel nor the fuel/memory config.

### H4 — Host I/O contract: XTEST-over-host-socket input + out-of-band framebuffer scrape + C6 DoD
**What:** In the product path: (1) Input is injected by the **host** speaking X11+XTEST `FakeInput` via x11rb directly to the X server's host-backed AF_UNIX socket `<shadow>/tmp/.X11-unix/X0`, **bypassing the guest** — because live `WriteStdin`/post-start file delivery to a running guest does **not** propagate. (2) The host reads the framebuffer **out-of-band** by globbing the sidecar's private shadow dir (`secure-exec-sidecar-shadow-<vm_id>-<nonce>/data/Xvfb_screen0`, BGRX→RGBA) off host disk, because an in-band wire `Pread` "gets starved and never returns" under load. (3) **C6 correction:** a static FB scrape proves nothing about interactivity — XU7 acceptance **requires an in-band input→visible-response proof measured over the wire**, not a host-side FB read.
**Evidence:** host/src/main.rs:373–377/:538–540/:928–931 (broken live delivery), :394–625 (XTEST module), :1538–1577 (inject), :1579–1637 (shadow scrape + starvation rationale); host/Cargo.toml (x11rb xtest); SPEC.md M6-INTERACTIVE:302–325; XUBUNTU-SPEC.md C6:111–114; crates/sidecar/src/vm.rs:1592.
**Verdict:** KEEP-AS-DESIGN. **Fold into:** D1/Root-2 design (these are the *consumer side* of the single-sync-RPC-thread bottleneck) + NEW host-port DoD. Both are dead-cap patterns that work only because host+sidecar share a filesystem; a remote-client AgentOs must surface frames/input through a supported channel (working inline K1 readback or an explicit host-backed mount/socket).

### H5 — XU7 per-isolate guest-state divergence beyond host_net (the multi-app blocker)
**What:** Under wasi-threads each worker is its own V8 isolate with fresh/empty copies of state Linux shares across threads. K3a covers only the **host_net-socket** slice. **Still unfixed:** `syntheticFdEntries` (guest-file fds → spurious cross-thread `EBADF`) and `spawnedChildren`/`proc_waitpid` (→ spurious cross-thread `ECHILD`). The single generalizing fix = **kernel-as-shared-source-of-truth + range-encoded fds + per-isolate cache with kernel-resolve fallback**.
**Evidence:** XUBUNTU-SPEC.md Direction banner lines 18–26; full audit at `~/progress/.../2026-06-27-isolate-divergence-audit/audit-report.md`.
**Verdict:** KEEP. **Fold into:** extend **K3a** to name the two unfixed members + the generalizing fix. This is the concrete blocker that keeps XU7 red.

### H6 — Constraints #1/#2 + trust-model (the substrate + TCB boundary)
**What:** Two non-negotiable governance constraints: (a) the process that executes the guest **and** renders is the **standard secure-exec Rust client** (`crates/secure-exec-client`); **forbidden** in the exec/render path: wasmer, node:wasi, the TS client, any `Command::new` direct spawn (M0 wasmer/node:wasi spike is **superseded**, kept only as determinism evidence). (b) X server + toolkit + app all run as **untrusted guests**; the only new trusted host code is the native-surface shuttle, which does **no protocol parsing** (blits an opaque pixel buffer, forwards input).
**Evidence:** SPEC.md §1a.2:28–37, §2:81–84.
**Verdict:** KEEP-AS-DESIGN. **Fold into:** NEW design preamble **D6**. Without it a re-impl could rebuild on the wrong substrate or move X-protocol parsing into trusted host code.

### H7 — libxcb-threads / libX11-threads single-threaded-deadlock fidelity patches
**What:** The vendored `-threads` X client libs carry two load-bearing patches that make `gtk_init` complete: (1) **MONOTONIC time-bounded `pthread_cond_timedwait` (~4ms)** replacing infinite `pthread_cond_wait` in libxcb socket-handoff/reply-notify loops (`_xcb_cond_*` in libxcb-threads/src/xcb_conn.c; `_X_xcond_*`/`_X_xcond_init_monotonic` in libX11-threads/src/locking.c) — libs built with the wasi-threads ABI but the guest is single-threaded, so an intra-process broadcast is missed and the client parks forever; MONOTONIC is mandatory because **CLOCK_REALTIME is frozen** (see L-info). (2) **Recursive X display mutexes** (`_X_xmutex_init_recursive`) so `LockDisplay` re-entry at `XRRGetOutputInfo` does not self-deadlock.
**Evidence:** WASM-THREADS-SPEC.md §0b:119–140; third_party/libxcb-threads/src/xcb_conn.c:61–82,505; third_party/libX11-threads/src/locking.c:61–89.
**Verdict:** KEEP. **Fold into:** extend **K15** sanctioned-patch list — it currently lists only Xvfb *server* patches (keymap-no-xkbcomp, vfb-randr). This is a different *client-side* threaded-ABI patch family; without it the runtime hangs at `XOpenDisplay`/`XRRGetOutputInfo`.

### H8 — FFI keystone: exact 6-arg host-import ABI + per-calling-isolate table routing
**What:** Two D5 details the manifest's `ffi_call(fn_index,…)` shorthand omits: (a) The wire contract is `__se_ffi_call(unsigned fn_index, unsigned ret_kind, unsigned nargs, const unsigned char *arg_kinds, const void *arg_vals, void *ret)` imported as `host_net.ffi_call`, kind codes `0=i32,1=i64,2=f32,3=f64,255=void`, **fixed 8-byte slot per arg/return**, `wasm_kind` collapses pointer + all ≤32-bit ints to `0`. Host import and shim must agree byte-for-byte or every GObject marshal corrupts. (b) Under K2 wasm-threads, concurrent `ffi_call` from N workers must each reflect on **that calling isolate's** `indirect_function_table` — a process-global table silently calls the wrong function under concurrency. (The manifest's "only reaches the guest's own table" is a *confinement* statement, not the *which-of-N-isolates* routing requirement.)
**Evidence:** libffi-wasm/src/ffi.c:13–16,50–90; guest-xclient/ffi-spike.c:15–18; guest-xclient/threads-ffi.c:1–28.
**Verdict:** KEEP. **Fold into:** extend **D5**. Required to re-seat the host import into main's rewritten `node_import_cache.rs`.

### H9 — Mandatory fixture-staging set + fork/proc_spawn route-around fixtures (DoD)
**What:** Every render/bench depends on a staged fixture set the plan never enumerates: prepare-fonts/xftfonts (else fontconfig errors → all glyphs become `.notdef` TOFU while a **high non-black % MASKS the failure**), prepare-locale, stage-gschemas, prepare-xkb (precompiled `/xkb/default.xkm`, else keyboard never activates and keyboard apps trap), prepare-dbus-fixtures, prepare-icons, mounted as `--vm-tree vmxu5sess/vmicons/vmxft/vmschemas/vmxkb`. Critically, these scripts **exist because there is no fork/proc_spawn**: prepare-xfce4-panel.sh sets `configver=2` to skip the first-run `fork(xfce4-panel-migrate)`, forces `X-XFCE-Internal=TRUE` per plugin to avoid the per-plugin wrapper fork, and stages stub `<name>.so` files (plugins are statically gmodule-shim-linked); prepare-menucache/rootmenu pre-stage the freedesktop `.menu/.desktop/.directory` trees that `menu-cache-gen`/garcon would otherwise build via subprocess.
**Evidence:** scripts/render-app.sh:9–13,37; scripts/prepare-xfce4-panel.sh:4–9,19; prepare-menucache-fixtures.sh; prepare-rootmenu-fixtures.sh; bench-suite.sh:16–21.
**Verdict:** KEEP. **Fold into:** NEW DoD item; couple to §5.1 proc_spawn. A re-impl that ports runtime but not the fixture layer reproduces zero screenshots and silently renders TOFU that passes non-black coverage. Record (a) the exact required fixture/vm-tree set, and (b) that these fixtures **are** the current stand-in for missing fork — they define what breaks until proc_spawn lands.

## 2. HIGH-SEVERITY CORRECTIONS TO THE PLAN

### C1 — "glyph 64ms" is RETRACTED as a floor (and the governance rule now forbids unproven floors)
The manifest lists "glyph 64ms" under **IRREDUCIBLE FLOORS**, but PERF-OPTIMIZATION.md's final word (2026-06-30) explicitly retracts it: native renders the identical glyph in ~10ms (same trustworthy method, Docker), so the ~54ms gap is **runtime-induced**, **<10ms is reachable in CORE**, and the live lever (T-wake cross-guest round-trip, HOPPROF peerWait ~1.6ms/round-trip vs native µs) is **OPEN**. Reinforced by the new CLAUDE.md rule: *"A perf gap vs native Linux is a runtime bug until a 1:1 native trace proves otherwise — never call it a floor"* (cites the ~50ms keystroke nearly mis-written-off as an 8ms GTK frame-clock floor that strace proved was a poll_wait wake-latency bug).
**Evidence:** PERF-OPTIMIZATION.md:268–282,367–368,384; CLAUDE.md (diff) new bullet.
**Action:** Demote glyph-64ms from D4 FLOORS to an OPEN runtime lever with a native ~10ms reference; add the 1:1-native-strace requirement as a durable methodology gate. Also re-examine B0 ~1.97s / B1 GObject 2.8x / 250µs-pump under the same rule (the plan's "re-establish these numbers on main" line is weaker than this governance constraint).

### C2 — Wakeups are event-driven; the K3c ~10ms timer cap removal is MANDATORY, not optional
New CLAUDE.md invariant: a blocked guest poll/`net.poll_wait`/futex must be woken by an explicit readiness notify routed to **every** cross-process waiter; **never** add a timer/poll fallback (e.g. capping a block at 10ms to re-scan the fd set). The only sanctioned periodic scan is an opt-in, **default-OFF missed-wake DETECTOR** that flags/logs (never silently completes the wait). The plan's K3c keeps the "~10ms cap when the set has pipes" as a "redundant safety net" and frames its removal as optional ("safe to drop once the notify graph is proven"). The governance rule makes removal mandatory and bans re-introducing any such fallback.
**Evidence:** CLAUDE.md (diff) "Wakeups are event-driven, never timer-polled."
**Action:** Re-word K3c: timer cap is to be removed, not retained; add the default-OFF missed-wake detector as the only allowed scan.

### C3 — ir gate number: plan's "≈64ms" conflates glyph-RENDER floor with input-response ir (~100ms)
The plan's Phase-3 gate targets "ir on the trustworthy glyph metric ≈ 64ms" (REIMPLEMENT:293). bench-ir.sh (2026-06-30, newest) states the **true warm single-keystroke ir is ~100ms**, was mis-read as ~20–88ms, and that 64ms is the glyph-*render* floor, a different quantity. The gate number is likely wrong/unreachable as written.
**Evidence:** scripts/bench-ir.sh:6–9,21–29; plan:293,45,269.
**Action:** Reconcile the Phase-3 gate against bench-ir.sh — separate glyph-render floor from input-response ir, and restate the target on the trustworthy metric.
