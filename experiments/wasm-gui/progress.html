2026-06-26 (PST)
★ Built a trap symbolizer → fixed the keyboard dialog (5th settings dialog). The "silent trap" class (apps that died with a bare RuntimeError: unreachable) was opaque only for lack of a symbolizer — the in-binary names approach bloats big GTK guests past the 64 MB frame cap. Key observation: the runtime does print trap frames as wasm-function[N]. So an address-based symbol map works: re-fpcast a KEEP_NAMES binary just to extract --symbolmap (never run it), then strip only the name section (indices preserved) to get a runnable index-matched binary. That resolved xfce4-keyboard-settings's trap to a GLib fatal log: Invalid object type 'XfceTitledDialog' — the libxfce4ui dialog base type wasn't registered (the 3 rendering dialogs force-register it; the keyboard doesn't, and the static no-dlopen build doesn't auto-register). Fixed in the platform layer (constraint #5): a build-linked shim that wraps gtk_init_with_args to ensure the type — keyboard source untouched. The dialog now renders fully (Behavior / Application Shortcuts / Layout tabs, repeat sliders, Test area), exit 0. The symbolizer is reusable for the remaining silent traps (the settings grid, theme enumeration). Proof: gui-progress/2026-06-26T12/xu6-keyboard.png.

2026-06-26 (PST)
★ The multi-session wasm-EH blocker is RESOLVED — the terminal reaches the spawn. Unmodified VTE (the xfce4-terminal engine) now links, renders, constructs the terminal widget, opens the pty (openpt rc=0), runs the full pty setup (grantpt/unlockpt/TIOCSWINSZ), and reaches vte_terminal_spawn_async — all wasm.
Root cause (after a long mis-diagnosis as "type_info won't link"): a TLS-consistency issue with libunwind's __wasm_lpad_context. clang -fwasm-exceptions emits TLS access for it in threaded TUs, so the EH runtime must be built all-threads (one non-threads object demotes the whole TLS segment → lsda=0 → typed catches escape → terminate). Codified in toolchain/build-libwasmeh.sh; proven on a minimal threaded catch(int) (lsda=0x480, catches).
The only remaining terminal gate is now wiring host_process.proc_spawn (the actual /bin/sh launch) — the surfaced fork/process-spawn TCB decision.
